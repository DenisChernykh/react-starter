# Руководство по TSDoc

Этот документ описывает отдельную, явно запрошенную TSDoc-задачу для
`react-starter`. Обычная разработка и `pnpm check` не требуют добавлять или
обновлять TSDoc.

## Цель

- Делать экспортируемый контракт понятным без чтения полной реализации.
- Фиксировать побочные эффекты, требования к провайдерам, cache/session-инварианты, навигацию и fallback-поведение.
- Сохранять комментарии полезными: описывать контракт, а не пересказывать строки реализации.

## Область действия

Если задача посвящена TSDoc, документируй экспортируемый рукописный
TypeScript/TSX API:

- `export function`;
- React-компонентов;
- хуков;
- `export type`, `export interface` и `export enum`;
- экспортируемых `const`, если это модульный API, helper, конфигурация, mapping или cache key.

Не документируй вручную сгенерированные артефакты:

- `src/shared/api/generated/**`;
- `src/shared/api/generated-zod/**`.

Проверка запускается отдельно:

```bash
pnpm lint:tsdoc
```

Она выводит замечания как warnings и не является частью `pnpm lint` или
`pnpm check`.

## Стиль

- Текст TSDoc пиши на русском языке.
- Идентификаторы и inline-код сохраняют исходное написание и оформляются в обратные кавычки.
- Краткий summary обязателен и объясняет назначение API.
- Добавляй `@remarks`, когда есть побочные эффекты, требования к провайдерам, cache/session-эффекты, навигация, fallback-поведение или неочевидные инварианты.
- Добавляй `@param`, только если контракт параметра не следует из имени и типа.
- Добавляй `@returns`, когда результат имеет значимый контракт: для хуков, cache helpers, nullable значений или ветвящегося поведения.
- Добавляй `@example`, только если пример устраняет реальную неоднозначность.

## React-компоненты и хуки

Кратко документируй все экспортируемые компоненты и хуки.

Добавляй `@remarks`, если компонент или хук:

- требует React Router, React Query или другой provider;
- выполняет navigation, mutation, notification или cache update;
- рендерит важный loading, error, forbidden или fallback state;
- синхронизирует внешний browser API через `useEffect`.

Не документируй тривиальные pass-through props, например `children` или `className`, если они не меняют поведение.

## API, кеш и сессия

Для API-client, session и cache helpers фиксируй в `@remarks`:

- какие запросы или мутации выполняются;
- как обновляется, инвалидируется или очищается кеш;
- какие состояния намеренно не повторяются или не восстанавливаются;
- security-инварианты, например CSRF и защита от устаревшего async-результата;
- важные HTTP fallback-ветки и нормализацию ошибок.

## Тесты

- `describe`, `it` и `test` не требуют TSDoc.
- Экспортируемые или неочевидные test helpers документируй.
- Простые сценарии выражай понятными названиями тестов, а не комментариями.

## Антипаттерны

Не допускаются:

- пустые комментарии;
- пересказ имени API без его контракта;
- построчный пересказ реализации;
- устаревшие или вводящие в заблуждение комментарии;
- формальные `@remarks`, `@param` или `@returns` без дополнительной пользы;
- ручное документирование сгенерированных файлов.
